- Content Score 2.0 is computed only in `supabase/functions/_shared/score-v2.ts` (weighted formula, deterministic Technical GEO); the LLM never supplies the overall score — keeps scoring auditable and non-fabricated.
- Analyses without `score_version` are legacy and are never recalculated or compared numerically with 2.0 — preserves history integrity.
- Technical GEO is a versioned deterministic ruleset in `supabase/functions/_shared/technical-geo.ts` (TECHNICAL_GEO_RULESET_V1, heuristic_weights_v1); score = earned/applicable points, not_applicable and unavailable excluded, coverage kept separate — page-type-aware and auditable.
- Successful analyses are persisted via `_shared/persist.ts` `buildAnaliseRow` (app → origem "app", API → "webhook_api"); failures never become history rows — one row shape for all entry points.
- Score 2.0 diagnosis presentation logic lives in `src/lib/diagnosis.ts` (pure, reads persisted fields incl. `weights_applied`, never recalculates with hardcoded weights); UI tests run with `bun test tests/` — keeps the UI auditable and separate from score math.
- Brand Brain: one `brand_brains` row per version (one active per empresa), provenance-tagged child tables `brand_*`; written only via service-role RPC `persist_brand_brain` (atomic, carries `origin='user_edit'` rows forward), normalization in `supabase/functions/_shared/brand-brain.ts` — structured, versioned, never invented.
- Brand Profile writes go only through edge function `brand-profile` (auth, active-version ownership, validation in `_shared/brand-profile-ops.ts`, rate limit, `brand_audit_log`); extracted rows are never edited — corrections are `user_edit` rows with `supersedes_id`, reviews use `human_status`; precedence lives in `_shared/brand-precedence.ts` — observations stay auditable.
- Brand Alignment 1.0 is computed only in `supabase/functions/_shared/brand-alignment.ts` (fixed weights, redistribution over available dimensions, model refs validated against context IDs) and is never combined with Content Score — two independent axes.
- Brand-aware context is built by `_shared/brand-context.ts` from the server-resolved ACTIVE Brand Brain (user→workspace→empresa), with explicit relevance/budget exclusions; the snapshot is stored on `analises.brand_context_snapshot` and history reads only it — past analyses never change.
- Brand precedence lives in `_shared/brand-precedence.ts` (dependency-free) and is re-exported by `src/lib/brand-profile.ts` — one implementation for server and UI.
- Problem↔offering links are stored by ID in `brand_problem_offerings` (auto-linked by DB triggers; legacy name arrays kept) — stable references across edits.
